## 4주차 발표자 조현진 OmniParser 리뷰

### 논문: OmniParser for Pure Vision Based GUI Agent (Microsoft Research, 2024.08)
코드: https://github.com/microsoft/OmniParser
요약:
HTML 없이 스크린샷만으로 번호 마커를 생성해 GPT-4V의 ScreenSpot 성능을 16.2에서 73.0으로 상승

## 내용 정리

### 1. 문제

SoM은 번호를 붙이면 된다고 했으나 그 번호를 어디에 붙일지는 DOM에서 파싱해 가져옴. 논문은 기존 SoM 기반 해법들이 행동 가능 요소의 박스를 뽑기 위해 파싱된 HTML 정보에 의존하며 이것이 용도를 웹 브라우징 과제로 제한한다고 지적.

되는 환경: 웹 브라우저(DOM 트리), 안드로이드(뷰 계층)
안 되는 환경: 윈도우/맥OS 데스크톱 앱, PhotoShop, Office365, 게임, 임의의 화면

논문 주장: 기존의 순수 비전 기반 화면 파싱이 만족스럽지 못해 GPT-4V의 이해 능력이 심각하게 과소평가되고 있음 -> GPT-4V가 UI를 못 보는 게 아니라 우리가 잘 보여주지 못한 것이라는 프레이밍

### 2. 설계 방향
복잡한 과제 수행을 위해 모델이 해야 하는 일 두 가지: 현재 화면 이해, 다음 행동 예측
-> 둘을 한 번의 호출로 시키지 않고 의미 추출을 파싱 단계에서 미리 분리하면 GPT-4V의 부담이 줄어 행동 예측에 집중 가능

### 3. 방법: 모듈 3개
아이콘 탐지: YOLOv8으로 상호작용 가능 영역 탐지
OCR: 텍스트 박스 추출, 아이콘 박스와 겹침이 90% 넘으면 제거
아이콘 설명: BLIP-2로 각 아이콘의 기능 설명 생성

출력 두 가지: 번호와 박스가 씌워진 스크린샷, 텍스트와 아이콘 설명을 담은 local semantics
-> DOM 비슷한 구조화된 표현을 비전만으로 복원

### 4. 데이터셋
적절한 공개 모델이 없어 두 개를 직접 제작

탐지용 6만 7천 장: ClueWeb22 인기 URL 10만 개를 샘플링해 각 페이지 DOM 트리에서 박스 수집. YOLOv8 20에폭, 배치 256, GPU 4장
설명용 7,185쌍: 탐지된 아이콘 박스를 GPT-4o에 넣어 기능을 한 문장으로 설명하게 함. 아이콘이 아니면 그 사실도 데이터에 포함. BLIP-2 1에폭 파인튜닝

DOM 의존을 없애려고 DOM으로 학습 데이터를 만들었으나 추론 시점에는 불필요
파인튜닝 효과: 톱니바퀴를 회색과 흰색의 톱니바퀴 이미지로 설명하던 것이 Settings로 바뀜. 모양 묘사에서 기능 설명으로 전환

### 5. SeeAssign
저자들이 직접 만든 112개 과제. 박스 개수로 난이도 구분(쉬움 10개 미만 / 보통 10~40개 / 어려움 40개 초과)

조건	쉬움	보통	어려움	전체
설명 없음	0.913	0.692	0.620	0.705
설명 있음	1.00	0.949	0.900	0.938

박스가 많아질수록 번호를 잘못 할당함. SoM이 박스를 많이 붙일 수 있다는 점을 장점으로 내세웠으나 많이 붙이면 오히려 틀림
설명을 붙이면 어려움 구간이 0.620에서 0.900으로 회복, 전체 평균보다 개선 폭이 큼
논문은 설명이 없으면 과제가 요구하는 아이콘과 실제 번호를 연결하지 못해 환각으로 이어진다고 분석

### 6. 결과
ScreenSpot (평균)

방법	점수
GPT-4V	16.2
CogAgent (18B, GUI 파인튜닝)	47.4
SeeClick (9.6B, GUI 파인튜닝)	53.4
OmniParser 설명 없음 + Grounding DINO	58.4
OmniParser 설명 추가	68.7
OmniParser 설명 + 자체 탐지 모델	73.0

같은 GPT-4V인데 화면을 보여주는 방식만 바꿔서 16.2에서 73.0으로 상승. GUI 데이터로 파인튜닝된 모델들을 프롬프팅만으로 이김
설명 추가 +10.3, 탐지 모델 교체 +4.3
데스크톱 Icon/Widget 항목은 11.8에서 63.6

Mind2Web (Step Success Rate)

방법	HTML 없음	Cross-Website	Cross-Domain	Cross-Task
GPT-4 (HTML 사용)	X	30.1	26.4	36.2
GPT-4V + SoM (HTML 박스)	X	32.7	23.7	20.3
GPT-4V + textual choice	X	32.4	36.8	40.2
OmniParser	O	36.5	42.0	39.4

HTML을 쓰지 않고 HTML을 쓴 GPT-4를 모든 하위 범주에서 앞섬. textual choice 대비 Cross-Website +4.1, Cross-Domain +5.2, Cross-Task만 -0.8
저자들은 OmniParser가 DOM의 정답 요소 정보보다 더 높은 품질의 정보를 제공한다고 해석
AITW(모바일)에서도 GPT-4V + history 53.0에서 57.7로 상승. 웹페이지로 학습한 탐지 모델이 모바일 화면에 일반화됨

### 7. 실패 사례
반복되는 요소: 알람 화면에 동일한 토글 7개, 정답은 27번이나 오답. 생긴 게 같으면 번호를 붙여도 구별할 근거가 없음 -> 반복 요소에 더 세밀한 설명 추가 제안
박스 입도: MORE 텍스트를 감싸는 더 큰 박스를 잡았는데 클릭 지점을 박스 중심으로 계산해 실제 영역 바깥에 떨어짐. OCR에는 클릭 가능 여부라는 개념이 없음 -> OCR과 탐지를 하나로 합친 모델 제안
아이콘 오해석: 점 세 개 아이콘을 로딩 또는 버퍼링 표시기로 설명. 설명 모델이 잘라낸 아이콘만 볼 뿐 전체 그림을 보지 못함 -> 전체 맥락을 보는 설명 모델 제안

논문에서는 세가지 문제의 해법 모두 future work로 남김

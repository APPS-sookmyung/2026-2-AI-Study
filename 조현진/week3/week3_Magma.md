## 1. 문제 정의

### 지금까지의 VLA 환경

에이전트 모델들이 디지털 영역 / 물리 영역으로 분리되어 있었음.

| 환경 | 대표 모델 |
|---|---|
| 디지털 (UI 내비게이션) | Pix2ACT, Ferret-UI |
| 물리 (로봇 조작) | RT-2, OpenVLA |

논문은 이들이 범용(generalist)을 표방하지만 실제로는 특정 행동 정책 학습에 집중한 대가로 일반적인 멀티모달 이해 능력이 크게 떨어지고, 결과적으로 다룰 수 있는 작업과 도메인의 폭이 좁아졌다고 지적함.

### 목표

논문이 정의하는 멀티모달 에이전트는 두 가지를 동시에 가져야 함.

- **Multimodal Understanding**: 디지털이든 물리든, 의미뿐 아니라 공간적·시간적으로도 입력을 이해
- **Multimodal Action Prediction**: 작업을 행동 시퀀스로 옮기고 정확하게 실행

-> 이 시스템은 사람이 준 목표에 의해 움직여야 함. 즉 "보고 이해하는 모델"과 "행동하는 모델"을 하나로 합치겠다는 의도.

## 2. 핵심 난제: 출력 공간 문제

수식:

```
O^l = π(I, task)        l ∈ {verbal, spatial}
```
l에 따라 출력이 좌우됨.

| 작업 | 출력 |
|---|---|
| UI 내비게이션 | 행동 종류(click, type 등) + 위치 (x, y) 또는 박스 (x, y, w, h) |
| 로봇 조작 | 6자유도 변위 (x, y, z, yaw, pitch, roll) + 그리퍼 개폐 |
| VQA | 텍스트 설명, 경우에 따라 위치 |


1. **사전학습 목표**: UI는 2D 위치를 예측하는데 로봇은 2D 이미지에 근거하지 않는 고유수용성 행동을 만든다. 공동 학습이 가능한 통합 인터페이스를 어떻게 만들까? 이 간극을 메울 대리 과제(surrogate task)를 찾을 수 있을까?
2. **데이터 규모**: 기존 VLA 데이터는 양도 다양성도 부족하다. 가장 큰 로봇 데이터셋인 Open X-Embodiment도 환경이 22개뿐이고 궤적은 약 100만 개다. 반면 영상에는 사람의 행동과 물체 상호작용이 넘쳐난다. 이 영상 데이터를 에이전트 사전학습에 쓸 수 없을까?

## 3. 해법: SoM + ToM

### 3-1. SoM으로 행동을 grounding

SoM 논문(Yang et al., 2023)의 아이디어를 가져오되, 용도를 다르게 사용함.

| | SoM 원논문 | Magma |
|---|---|---|
| 목적 | 기성 LMM을 프롬프팅 | 시각 프롬프트를 인식하도록 모델을 학습 |
| 대상 | GPT-4V | 자체 학습하는 에이전트 모델 |

모델 입장에서 **원래의 2D·3D 출력을 예측하는 것보다 숫자 마커를 고르는 게 훨씬 쉽다**고 판단함. 그래서 식 (1)을 수정함.

```
o_t^mark = {action_t : mark_t} = π(I_t^M, task)
```

클릭할 버튼도 "3번", 집을 물체도 "3번". 출력이 숫자 하나로 통일 가능 -> UI와 로봇을 한 모델에 넣을 수 있게 됨

#### SoM 생성 방식에서 원논문과의 차이점 (Algorithm 1)


| | SoM 원논문 | Magma Alg. 1 |
|---|---|---|
| 후보 영역 | 세그멘테이션 모델 (SAM, SEEM 등) | 웹은 DOM 트리, 모바일은 뷰 계층 |
| 마커 위치 | distance transform — 경계에서 가장 먼 **내부 점** | `FindOptimalCorner` — 이미 그린 박스들로부터 가장 먼 **모서리** |

사물 가나 겹침을 최소화한다는 목적은 같으나 구현이 다름. 순서도 같은 구조로 진행. 박스를 그리고 → 이전 박스들을 고려해 라벨 위치를 정하고 → 텍스트 박스 크기를 계산해 좌표를 할당.


### 3-2. ToM으로 행동을 계획

SoM을 시간 축으로 확장한 것.

```
o_t^mark = {action_t : mark_t : trace_(t+1:l)}
         = π({I_1, ..., I_(t-1), I_t^M}, task)
```

현재 프레임의 마커가 다음 l 프레임 동안 어디로 이동하는지 궤적을 예측.

#### 왜 궤적을 예측해야 하는가?

논문이 드는 이점 두 가지가 설득력 있다.

1. 모델이 행동하기 전에 시간을 앞서 보도록 강제한다. 영상의 시간적 역학을 이해해야 궤적을 맞출 수 있기 때문.
2. 다음 프레임 자체를 예측하는 방식과 비교하면, 토큰을 훨씬 적게 쓰면서 더 긴 시간 지평을 담고 주변 배경은 무시할 수 있음. 프레임 통째로 그리는 건 비싸고 불필요한 정보가 많은데, 점 몇 개의 궤적은 싸고 행동과 직결됨.

#### ToM 생성 (Algorithm 2)

```
1. CoTracker로 픽셀 단위 궤적 추출 (s×s 격자 점, s=15)
2. 카메라 전역 움직임이 있으면 → 호모그래피 변환으로 제거
3. 움직임 크기 기준으로 전경/배경 궤적 분리 (임계값 ε=2)
4. 전경·배경을 각각 K-means로 클러스터링
5. 클러스터마다 대표 점을 골라 최종 궤적으로
6. 첫 프레임에 SoM 적용
```

2단계의 중요성: 카메라가 흔들리는 영상은 궤적에 작업과 무관한 움직임이 섞이는데, 현재 마커 위치와 미래 마커 위치로 3×3 변환 행렬을 구해서 같은 좌표계로 맞춤. 논문은 이 방법이 1인칭 영상과 3인칭 영상 양쪽에서 전역 카메라 움직임 제거에 효과적이라고 보고.

### 3-3. 학습

SoM/ToM 주석을 원래 텍스트·행동 주석과 합쳐 공동 사전학습. 모든 주석을 언어 토큰으로 변환.
- 2D 행동 → 텍스트 딕셔너리
- 로봇 행동 → LLM의 마지막 256개 이산 토큰
- 좌표는 이미지 크기로 정규화 후 256구간으로 양자화

백본은 LLaMA-3-8B + ConvNeXt-XXlarge (임의 해상도 지원). 학습률 1e-5 고정, 최대 3에폭, 언어 모델과 비전 인코더 전체를 튜닝.

## 4. 데이터

총 3,900만 샘플. 

| 종류 | 데이터셋 |
|---|---|
| 멀티모달 이해 | ShareGPT4V, LLaVA-1.5 instruction tuning, OCR 관련 (= Magma-SFT 820K) |
| 로봇 조작 | Open X-Embodiment |
| UI 내비게이션 | SeeClick, Vision2UI |
| 교육용 영상 | Epic-Kitchens, Ego4D, Something-v2 등 목표 지향 인간 행동 영상 |

전부 SoM과 ToM으로 자동 라벨링 원래 행동 라벨이 없던 이미지와 영상을 "비전-언어-행동" 데이터로 변환했다는 것이 이 논문의 실질적 기여.

## 5. 결과

### 5-1. Table 3 ablation — 이 논문의 진짜 주장



| 조건 | SoM+ToM | VWB-Ele-G | VWB-Act-G | SE-Bridge | SE-Google |
|---|---|---|---|---|---|
| Magma-8B (UI) | ✗ | 68.5 | 58.3 | - | - |
| Magma-8B (OXE) | ✗ | - | - | 22.2 | 35.7 |
| Magma-8B (ACT) — UI+로봇 | ✗ | 89.1 | 21.4 | 17.5 | 31.5 |
| Magma-8B (Full) | ✗ | 90.1 | 25.2 | 17.7 | 37.5 |
| Magma-8B (Full) | ✓ | **96.3** | **71.8** | **35.4** | **52.3** |

표 해석

1. 위 세 줄: **UI 데이터와 로봇 데이터를 그냥 합치면 오히려 양쪽 다 성능이 하락함.** 이미지 도메인도 행동 공간도(2D 좌표 vs 7자유도) 너무 다르기 때문.
2. 네 번째 줄: 영상 데이터를 추가해도 조금만 상승함. 영상 내레이션은 언어적 지능만 키우기 때문.
3. 마지막 줄: SoM과 ToM으로 전부 통일된 인터페이스에 넣고 나서야 이질적 데이터에서 효과적으로 학습도돰.

즉 이 논문의 기여는 "데이터를 많이 모았다"가 아니라 서로 다른 데이터를 같은 형식으로 바꾸는 방법을 찾았다는 점.

### 5-2. 제로샷 성능 (Table 1)

파인튜닝 없이:

| 지표 | Magma-8B | 비교 대상 |
|---|---|---|
| VWB-Ele-G | 96.3 | GPT-4V 67.5 |
| VWB-Act-G | 71.8 | GPT-4V 75.7 |
| SE-Google Robot | 52.3 | OpenVLA 31.7 |
| SE-Bridge | 35.4 | OpenVLA 14.5 |
| VQAv2 / TextVQA / POPE | 80.0 / 66.5 / 87.4 | LLaVA-1.5 78.5 / 58.2 / 85.9 |

- 전체 작업 스펙트럼을 수행할 수 있는 유일한 모델이라는 점이 표에서 드러남 (다른 모델들은 '-' 투성이)
- 로봇 조작에서 2위 OpenVLA를 20.8% 차이로 앞서 평균 성공률이 거의 두 배
- UI grounding 제로샷이 GPT-4V 기반 SOTA 방법도 추월함 (VWB 84.1 vs 71.6, 둘 다 OmniParser로 SoM 생성)

### 5-3. 파인튜닝 (Table 2, Fig. 6)

- Mind2Web 웹 UI 내비게이션: Cross-Website Step SR 45.4로 Qwen2-UIX(31.0), CogAgent(23.4) 등을 앞섬
- 실제 WidowX 로봇 4개 조작 과제: 평균 성공률 67.5% vs OpenVLA 25.0%. 처음 보는 과제("천을 왼쪽에서 오른쪽으로 밀기")에서도 우위

### 5-4. 공간·시간 추론 (Table 4, 5)

- VSR 65.1, BLINK-val 41.0 — SoM/ToM 없는 버전보다 개선
- 영상 QA에서 IntentQA 88.6으로 IG-VLM, SF-LLaVA 대비 약 28% 향상. 논문은 이를 ToM이 미래 프레임의 시간적 역학을 추론하게 만든 덕분으로 본다
- 영상 데이터를 학습에서 빼면 BLINK가 약 8% 떨어짐

## 6. 한계와 짚어둘 것

### 논문이 인정한 것

사후 학습(post-training) 단계가 없음. 그래서 지시를 잘 따르지 못하고, 답변 선택지를 온전히 출력하는 것을 어려워함, 논문은 각주에서 표준 옵션 매칭을 쓰면 성능이 크게 오른다고 밝힘. 벤치마크 숫자를 볼 때 감안할 부분.

### 표를 뜯어보면

Table 5의 SpatialEval Spatial Map에서는 SoM/ToM 없는 버전(41.5)이 있는 버전(33.9)보다 높음. Maze Navigation과 Spatial Grid에서는 반대로 SoM/ToM 쪽이 높음. **모든 공간 추론 지표에서 이기는 건 아님.**

## 7. SoM 원논문과 이어서 읽기

| | SoM (2023) | Magma (2025) |
|---|---|---|
| 위치 | 프롬프팅 기법 | 파운데이션 모델 |
| 마커의 역할 | 추론 시 입력을 바꾸는 장치 | **학습 신호** |
| 후보 영역 | 세그멘테이션 모델 | DOM/뷰 계층 (+ 평가 시 OmniParser) |
| 대상 모델 | GPT-4V (기성) | 직접 학습 |
| 시간 축 | 없음 | ToM으로 확장 |

SoM의 한계였던 "GPT-4V에서만 작동한다"를 Magma는 **아예 그 능력을 학습시켜 버리는 방식**으로 우회하여 해결함. 마커를 읽을 줄 아는 모델을 기다리지 말고 만들자는 것.

### 생각해볼 지점

- 조립은 요리나 물건 옮기기와 달리 되돌리기 어려운 순서가 있다. 궤적 예측만으로 "이 순서가 맞는가"를 판단할 수 있는가?
- Magma는 다음 행동을 예측하는 모델임. **출력을 마커+궤적이 아니라 사람이 읽을 수 있는 가이드로 바꾸면** 어떤 문제가 생기는가?
